# Подключение касс: что куда вписать

Адрес вебхука для кабинета провайдера: `https://<ваш-домен>/webhook/pay/<slug>`. Конструктор
показывает его под формой настроек. Секретные ключи вводите только в форме конструктора
(они шифруются), в чат и письма их не отправляйте.

Общий порядок для каждой кассы: 1) завести кабинет и тестовые ключи, 2) в конструкторе: бот →
«Оплата» → выбрать кассу → заполнить поля → оставить «Тестовый режим», 3) блок «Оплата» + блок
«Выдача», 4) оплатить с **другого** Telegram-аккаунта, 5) проверить по `docs/live-payment-tests.md`:
товар выдан один раз, продавцу пришло уведомление, статус в базе `paid`.

## ЮKassa (`yookassa`) — рубли
| Поле | Где взять |
|---|---|
| shopId | Кабинет → Интеграция → Ключи API |
| Секретный ключ | там же: `test_…` для теста, `live_…` для боя |
| Чек 54-ФЗ | Включать только если подключена онлайн-касса; тогда `fiscalization_enabled=1`, почта, ставка НДС |

В кабинете: Интеграция → HTTP-уведомления → адрес вебхука, событие `payment.succeeded`.
Тест: тестовый магазин создаётся самому (инструкция yookassa.ru/docs/support/merchant/payments/implement/test-store).

## CloudPayments (`cloudpayments`) — RUB, KZT, USD, EUR
| Поле | Где взять |
|---|---|
| Public ID (`pk_…`) | Кабинет → Сайты → Настройки |
| API-пароль | там же (API Secret) |

В кабинете: Настройки → Уведомления → Pay: адрес вебхука, метод POST. Новый сайт сразу в тестовом режиме.
Тестовые карты: `4242 4242 4242 4242` (успех), `4012 8888 8888 1881` (нет средств); срок любой, CVV любой.
Автопродления при оплате по ссылке не работают (нет токена карты), подписки выключены.

## Robokassa (`robokassa`) — рубли
| Поле | Где взять |
|---|---|
| Идентификатор магазина | Технические настройки → MerchantLogin |
| Пароль #1, пароль #2 | там же |
| Тестовые пароли #1, #2 | там же, отдельные для тестового режима |
| Алгоритм хэша | как в настройках магазина (по умолчанию md5) |

В кабинете: Result URL = адрес вебхука, метод POST. Тест: достаточно зарегистрировать кабинет,
активация магазина и документы для теста не нужны. Рекуррент возможен только после полной активации.

## PayMaster (`paymaster`) — рубли
| Поле | Где взять |
|---|---|
| merchantId | Кабинет мерчанта → список сайтов (UUID) |
| Токен доступа | Настройки → Токены доступа |

Адрес уведомления конструктор передаёт в каждом счёте, в кабинете вписывать не нужно.
У уведомления PayMaster нет подписи: мы всегда перепроверяем платёж запросом `GET /api/v2/payments/{id}`.
Тест: флаг `testMode` в счёте (включён «Тестовым режимом»); нужен кабинет мерчанта, ответа от PayMaster по доступу пока нет.

## lava.top (`lavatop`) — RUB, USD, EUR
| Поле | Где взять |
|---|---|
| API-ключ | Настройки аккаунта (заголовок `X-Api-Key`) |
| Почта для чеков | Ваша почта: Lava пришлёт чек на неё |

Товар и тариф заводятся в каталоге lava.top; в блок оплаты вставляется `offerId` оффера (ЛК → товар →
оффер). Цена берётся из оффера и должна совпадать с ценой в блоке. Адрес вебхука и авторизацию вебхуков
включить в ЛК. **Тестового режима в нашей интеграции нет** (флаг тестового режима ушёл бы в запрос, но
песочница у Lava не подтверждена), поэтому проверка — минимальный платёж настоящими деньгами на свой аккаунт.

## ioka (`ioka`) — только тенге
| Поле | Где взять |
|---|---|
| Client ID, Client Secret | Кабинет → Настройки → API |

Рабочий ключ мы получаем сами (`POST /v2/auth/token`) и обновляем; вебхук при первой оплате регистрируем сами.
Тестовая среда `stage-api.ioka.kz` выдаётся менеджером ioka: без неё проверка только настоящим платежом.

## Prodamus (`prodamus`) — рубли
| Поле | Где взять |
|---|---|
| Домен платёжной формы | `myshop.payform.ru`; для теста демо-магазин `demo.payform.ru` |
| Секретный ключ | Настройки → Интеграции |
| Ключ уведомлений | Только если выдан отдельно |

Адрес уведомления подставляется в каждой ссылке. Подписки Prodamus ведёт сам: в блоке оплаты указывается «ID подписки в Prodamus» (подписной товар из кабинета, цену и период задаёт он). В коде это есть, но вживую не проверялось, а подписки в запуске выключены (`SUBSCRIPTIONS_ENABLED=0`).

## Stripe (`stripe`) — USD, EUR, GBP, KZT, PLN, TRY, AED
| Поле | Где взять |
|---|---|
| Secret key | Stripe Dashboard → Developers → API keys: `sk_test_…` для теста, `sk_live_…` для боя |
| Webhook signing secret | Developers → Webhooks → добавить адрес вебхука, секрет `whsec_…` |

События вебхука: `checkout.session.completed`, `checkout.session.async_payment_succeeded`,
`checkout.session.async_payment_failed`, `checkout.session.expired`. Подпись вебхука проверяем, оплату
перепроверяем. Тест: режим test в Dashboard, карта `4242 4242 4242 4242`, срок любой, CVC любой.
Stripe недоступен плательщикам из РФ и Беларуси: для них нужны другие кассы.

## Без юрлица
- **Telegram Stars**: платёж мета-бота, подтверждает Telegram. Ключи не нужны.
- **Crypto Bot**: токен приложения в @CryptoBot (testnet для проверки).
- **«Оплата по ссылке»**: продавец сам подтверждает оплату кнопкой.
