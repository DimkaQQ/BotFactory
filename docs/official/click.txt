конфиденциальные-данные
Конфиденциальные данные

При регистрации поставщик услуг получает следующие данные для подключения и отправки запросов к API:


merchant_id

service_id

merchant_user_id

Хранение
secret_key
в открытом виде может привести к компрометации данных и несанкционированным операциям.



аутентификация
Аутентификация

Все запросы к API должны содержать HTTP‑заголовок:

Auth: merchant_user_id:digest:timestamp

Где:


digest
—
sha1(timestamp + secret_key)

timestamp
— UNIX timestamp (10‑значное количество секунд с начала эпохи)



пример-формирования-заголовка-auth-nodejs
Пример формирования заголовка Auth (Node.js)

language-js
import crypto from 'crypto'

// Укажите ваши ключи
const merchantUserId = 'YOUR_MERCHANT_USER_ID'
const secretKey = 'YOUR_SECRET_KEY'

// Получаем текущее время (Unix timestamp)
const timestamp = Math.floor(Date.now() / 1000)

// Формируем строку для подписи
const digestString = timestamp + secretKey

// Генерируем SHA1 хэш
const digest = crypto.createHash('sha1').update(digestString).digest('hex')

// Формируем Auth header
const authorization = `${merchantUserId}:${digest}:${timestamp}`

console.log('Auth:', authorization)

конфиденциальные-данные
Конфиденциальные данные

При регистрации поставщик услуг получает следующие данные для подключения и отправки запросов к API:


merchant_id

service_id

merchant_user_id

secret_key



secret_key
является конфиденциальным параметром. Поставщик услуг несёт полную ответственность за его безопасность.
Хранение
secret_key
в открытом виде может привести к компрометации данных и несанкционированным операциям.



аутентификация
Аутентификация

Все запросы к API должны содержать HTTP‑заголовок:

Auth: merchant_user_id:digest:timestamp

Где:


digest
—
sha1(timestamp + secret_key)

timestamp
— UNIX timestamp (10‑значное количество секунд с начала эпохи)



пример-формирования-заголовка-auth-nodejs
Пример формирования заголовка Auth (Node.js)

language-js
import crypto from 'crypto'

// Укажите ваши ключи
const merchantUserId = 'YOUR_MERCHANT_USER_ID'
const secretKey = 'YOUR_SECRET_KEY'

// Получаем текущее время (Unix timestamp)
const timestamp = Math.floor(Date.now() / 1000)

// Формируем строку для подписи
const digestString = timestamp + secretKey

// Генерируем SHA1 хэш
const digest = crypto.createHash('sha1').update(digestString).digest('hex')

// Формируем Auth header
const authorization = `${merchantUserId}:${digest}:${timestamp}`

console.log('Auth:', authorization)

описание-взаимодействия
Описание взаимодействия

Взаимодействие осуществляется через API-интерфейс, расположенный на сервере
Поставщика. API-интерфейс должен полностью соответствовать требованиям
данного документа.

Созданный платёж в системе
CLICK
передаётся по протоколу HTTP (HTTPS)
методом
POST
API-интерфейсу Поставщика услуг. Поставщик предоставляет
системе CLICK URL-адреса для взаимодействия с API-интерфейсом.

Взаимодействие разделено на два этапа:


Prepare

Complete


формат-взаимодействия
Формат взаимодействия

Запрос от CLICK отправляется с заголовком:


Content-Type: application/x-www-form-urlencoded


Тело запроса передаётся в формате form-data (urlencoded)

Ответ от Поставщика должен быть:


В формате
application/json

проверки-на-этапе-prepare
Проверки на этапе Prepare


Наличие и актуальность заказа / логина / лицевого счёта, а также возможность
отпуска товара или услуги.

Актуальность суммы заказа или оплаты.


Для интернет-магазинов при получении запроса Prepare Поставщик должен
зарезервировать товар для предотвращения повторной продажи.

Примечание.
При успешном ответе на запрос Prepare и успешном списании средств с карты,
ответ на запрос Complete не может быть ошибочным, за исключением случаев,
когда платёж уже был ранее подтверждён (
error = -4
) либо выполняется
повторная попытка подтверждения ранее отменённого платежа (
error = -9
).



При получении ошибочного ответа от Поставщика после нескольких попыток
платёж может быть переведён в состояние ручного разбирательства со стороны
Службы технической поддержки CLICK.
