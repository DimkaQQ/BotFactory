# Как подключить кассу: пошаговая инструкция для владельца бота

Эта инструкция для тех, кто хочет принимать деньги в своём боте. Деньги идут **напрямую вам**
в выбранную платёжную систему — конструктор их не принимает и не удерживает.

> **Про скриншоты.** Кабинеты платёжных систем закрыты логином, поэтому снимки экрана
> делаются с живого кабинета. В тексте ниже отмечено, где они нужны: `📷 docs/img/<имя>.png`.
> Названия пунктов меню в кабинетах иногда меняются; если пункта нет, ищите похожий по смыслу
> или напишите в поддержку кассы.

## Общий порядок (одинаков для любой кассы)

1. Заведите кабинет в платёжной системе и получите **тестовые** ключи.
2. В конструкторе откройте бота → кнопка **«Касса»** → выберите платёжную систему.
3. Впишите данные из кабинета (в инструкциях ниже сказано, где что взять). Секретные ключи
   вводятся только в эту форму: они хранятся зашифрованными. В чат, почту и соцсети ключи не
   отправляйте — если ключ утёк, перевыпустите его в кабинете кассы.
4. Оставьте режим **«🧪 Тестовый»** и скопируйте под формой **адрес уведомления** (вебхук) — его нужно
   вписать в кабинете кассы (там, где это требуется; у некоторых касс адрес передаётся сам).
5. В сценарии бота добавьте блоки **«Оплата»** (цена, название) и **«Выдача»** (что получит покупатель).
6. Пройдите оплату с **другого** Telegram-аккаунта (не с владельца бота).
7. Убедитесь: товар пришёл один раз, вам пришло уведомление о продаже. Повторное нажатие
   «Я оплатил» не должно выдавать товар второй раз.
8. Только после этого переключите режим на **«💰 Боевой»**, впишите боевые ключи и сделайте один
   платёж на минимальную сумму самому себе.

Что означают режимы:
- **🧪 Тестовый** — платёж ненастоящий, деньги не списываются. Нужны *тестовые* ключи кассы.
- **💰 Боевой** — списываются настоящие деньги, они идут вам. Нужны *боевые* ключи.
- **Демо-оплата** — это не касса: товар выдаётся сразу без денег, чтобы посмотреть сценарий.
  Бот с демо-оплатой опубликовать нельзя.

## Без юрлица: Telegram Stars, Crypto Bot, своя ссылка

### Telegram Stars
Ничего вписывать не нужно. Покупатель платит звёздами Telegram, подтверждает платёж сам Telegram.
Условия вывода звёзд и комиссии определяет Telegram (раздел про звёзды в настройках бота/Fragment) —
смотрите актуальные правила там. Для проверки: блок «Оплата» → оплатить с другого аккаунта.
📷 `docs/img/stars-1.png` — окно счёта в Telegram.

### Crypto Bot (USDT, TON)
1. В Telegram откройте **@CryptoBot** → **Crypto Pay** → **Create App** — получите **токен приложения**.
2. Для проверки используйте тестовую сеть: **@CryptoTestnetBot**, там тоже свой Crypto Pay и свой токен.
3. В конструкторе: «Касса» → Crypto Bot → вставьте токен. Режим «Тестовый» включайте, **только если токен
   от testnet** (токен testnet с боевой сетью даст ошибку 401 «Unauthorized»).
4. Адрес уведомления в кабинете вписывать не нужно.
📷 `docs/img/cryptobot-1.png` — Create App; `docs/img/cryptobot-2.png` — токен.

### Своя ссылка на оплату
Подходит, если кассы нет: например, ссылка на перевод. Бот пришлёт покупателю вашу ссылку, а вы сами
подтверждаете оплату кнопкой в боте — только после этого покупатель получает товар.
В блоке «Оплата» впишите ссылку (поле «Ссылка»).

## ЮKassa (рубли, нужно ИП/ООО или самозанятый по условиям ЮKassa)

Вписать в конструкторе: **shopId** и **Секретный ключ**.

1. Кабинет ЮKassa → **Интеграция** → **Ключи API**: там **shopId** и секретный ключ. Для теста создайте
   **тестовый магазин** (инструкция: yookassa.ru/docs/support/merchant/payments/implement/test-store),
   у него ключи вида `test_…`; у боевого — `live_…`.
   📷 `docs/img/yookassa-1.png` — раздел «Ключи API».
2. Кабинет → **Интеграция** → **HTTP-уведомления**: вставьте адрес из конструктора
   (`https://<домен>/webhook/pay/yookassa`) и включите событие **payment.succeeded**.
   📷 `docs/img/yookassa-2.png` — настройка уведомлений.
3. Чек 54-ФЗ включайте только если у вас подключена онлайн-касса: тогда в конструкторе включается
   фискализация, указывается почта и ставка НДС.
4. Тестовая карта ЮKassa — в их документации по тестовому магазину.

## CloudPayments (RUB, KZT, USD, EUR)

Вписать: **Public ID** и **API-пароль**.

1. Кабинет → **Сайты** → ваш сайт → **Настройки**: Public ID (`pk_…`) и **API Secret** (пароль для API).
   Новый сайт сначала работает в тестовом режиме.
   📷 `docs/img/cloudpayments-1.png`.
2. **Настройки → Уведомления → Pay**: адрес `https://<домен>/webhook/pay/cloudpayments`, метод **POST**.
   📷 `docs/img/cloudpayments-2.png`.
3. Тестовые карты: `4242 4242 4242 4242` — успех; `4012 8888 8888 1881` — «недостаточно средств».
   Срок и CVV любые.
4. Автопродления при оплате по ссылке не работают, поэтому подписки в запуске выключены.

## Prodamus (рубли)

Вписать: **Домен платёжной формы**, **Секретный ключ** (и «ключ уведомлений», если выдан отдельно).

1. Домен платёжной формы — адрес вида `myshop.payform.ru` (для проверки есть демо `demo.payform.ru`).
2. Секретный ключ: **Настройки → Интеграции**.
   📷 `docs/img/prodamus-1.png`.
3. Адрес уведомления подставляется в каждую ссылку автоматически — в кабинете ничего вписывать не нужно.
4. Разовые платежи работают по обычной ссылке. Подписки Prodamus ведёт сам (в блоке оплаты указывается ID подписки из кабинета), но в запуске они выключены и вживую не проверялись.

## Robokassa (рубли)

Вписать: **идентификатор магазина**, **Пароль #1**, **Пароль #2**, для теста — **тестовые пароли**.

1. Кабинет → **Технические настройки** магазина: идентификатор (MerchantLogin), Пароль #1, Пароль #2, а также
   отдельные тестовые пароли. Алгоритм хэша — как выбран в настройках магазина (обычно MD5).
   📷 `docs/img/robokassa-1.png`.
2. **Result URL** = `https://<домен>/webhook/pay/robokassa`, метод **POST**.
   📷 `docs/img/robokassa-2.png`.
3. Для теста достаточно кабинета: при регистрации укажите ИНН (ИП или юрлица), полную анкету заполнять не нужно. Дальше «Мои магазины» → «Добавить новый» → заполните карточку магазина (обязательно «Способ вывода средств») и технические настройки; отправлять магазин на активацию не нужно — его тестовые данные уже работают по API. Демо-магазин из документации Robokassa недоступен.
   Для боевых платежей магазин нужно полностью активировать (Robokassa запрашивает данные ИП/ООО/самозанятого).

## Stripe (USD, EUR, GBP, KZT, PLN, TRY, AED)

Вписать: **Secret key** и **Webhook signing secret**. Нужна компания/аккаунт в стране, где работает Stripe;
плательщикам из РФ и Беларуси Stripe недоступен.

1. Stripe Dashboard → **Developers → API keys**: секретный ключ `sk_test_…` (тест) или `sk_live_…` (бой).
   📷 `docs/img/stripe-1.png`.
2. **Developers → Webhooks → Add endpoint**: адрес `https://<домен>/webhook/pay/stripe`, события
   `checkout.session.completed`, `checkout.session.async_payment_succeeded`,
   `checkout.session.async_payment_failed`, `checkout.session.expired`. После создания откройте endpoint и
   скопируйте **Signing secret** (`whsec_…`).
   📷 `docs/img/stripe-2.png`.
3. Тестовая карта: `4242 4242 4242 4242`, срок и CVC любые.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Касса на кнопке «⚠️ не настроена» | Не заполнено поле — конструктор подскажет, какое |
| Покупатель оплатил, а товар не пришёл | Адрес уведомления вписан в кабинет кассы? Событие включено? Нажмите в боте «Я оплатил» |
| Ошибка 401 / «Unauthorized» | Ключ от другого режима: тестовый ключ при «Боевом» режиме или наоборот |
| Товар пришёл дважды | Не должно быть: сообщите в поддержку с номером заказа |
| Хочу вернуть деньги покупателю | Возврат делается в кабинете платёжной системы |

Юридическая часть (чеки, налоги, договор с платёжной системой) — на стороне владельца бота и
платёжной системы; при сомнениях проконсультируйтесь с юристом или бухгалтером.
