# Runbook: что делать, когда что-то случилось

Команды — на сервере, из каталога проекта. `docker compose` ниже — это
`docker compose -f docker-compose.yml -f docker-compose.shared-vps.yml`, если
сервис стоит на общем VPS (режим `shared`).

## Нарушитель: спам, мошенничество, запрещённый товар

1. Найди владельца: Telegram id виден в обращении в поддержку (пересланное
   сообщение) или в таблице `clients` (`telegram_user_id`).
2. Заблокируй:
   ```
   docker compose exec api python -m app.admin ban 123456789 --reason "спам"
   ```
   Вход в конструктор закрывается, все его боты ставятся на паузу (покупатели
   видят «бот на паузе»), отложенные сообщения отменяются, паузу сам владелец
   снять не может.
3. Если бот ещё и рассылает спам прямо сейчас — отзови токен у @BotFather
   (если токен известен) либо удали бота: `docker compose exec api python -m app.admin delete <id> --yes`.
4. Напиши владельцу через поддержку, что и почему. Разблокировать:
   `python -m app.admin unban <id>` (боты останутся на паузе).

## Запрос человека на выгрузку или удаление данных (GDPR)

* Выгрузка: `docker compose exec api python -m app.admin export <telegram_id> > export.json`
  — профиль, боты, блоки, платежи; без токенов и ключей. Отправь файл
  человеку в течение 30 дней.
* Удаление: `docker compose exec api python -m app.admin delete <telegram_id> --yes`
  — аккаунт, боты, блоки, подписчики, загруженные файлы. Платёжные записи
  остаются (бухучёт, срок хранения задаёт закон и бухгалтер), но от аккаунта
  отвязаны.
* Данные покупателей чужих ботов — отдельная роль: их оператор — владелец бота,
  а мы — обработчик. Запрос покупателя перенаправь владельцу бота.
* Резервные копии: старше 90 дней не держим. Раз в квартал очищай чат с
  бэкапами в Telegram и каталог `backups/` (`BACKUP_KEEP` уже ограничивает
  число копий на сервере).

## Возврат клиенту платформы (оплата запуска или продления)

Деньги вернуть можно только там, куда они пришли: в кабинете Stripe (Refund)
или Crypto Bot. Платформа сама бота не снимает и период не сокращает, поэтому
после возврата:
1. Реши, оставить ли бота на воздухе до конца периода.
2. Если нет — `ban`-ом не пользуйся (это для нарушителей); поставь в базе
   `UPDATE bots SET paid_until = now() WHERE id = '<uuid>'` — через час
   проверка периода уведёт его в льготный период, а затем снимет с эфира.
3. Платёж в таблице `payments` ставь в `refunded` вручную, чтобы учёт сходился.

Спор по карте (dispute/chargeback) приходит письмом от Stripe — отвечай там же
в срок; платформа события споров не обрабатывает.

## Потеряли доступ к серверу или сервер упал

1. Новый VPS → `deploy/deployfirst.sh` (он сам сгенерирует пароль базы и
   пропишет его в `.env`).
2. Расшифруй последний бэкап (команда написана в подписи к файлу в Telegram),
   подними базу: `docker compose exec -T db psql -U botfactory botfactory < db.sql`,
   верни `.env` и каталог `media/`.
3. `FERNET_KEY` из `.env` обязателен: без него токены ботов и ключи касс
   не расшифровать. Храни его копию отдельно от сервера.
4. Если бэкап пришёл «без файлов» (в подписи об этом сказано), файлы клиентов
   восстановятся только с самого сервера — подключи внешнее хранилище.

## Утечка токена бота клиента или ключей

* Токен бота: клиент отзывает его в @BotFather (`/revoke`) и вставляет новый.
* `FERNET_KEY`: `docker compose exec api python -m app.rotate_keys` по
  инструкции в README (добавь новый ключ первым, старый оставь вторым).
* `WEBHOOK_SECRET_KEY` менять нельзя без переустановки вебхуков — при смене
  перезапусти `api`, он переустановит их при старте.

## Проверка, что всё живо

* `curl -fsS https://<домен>/health` — 200 и `"database": "ok"`.
* Сторож (`deploy/watchdog.sh`) пишет в Telegram, если `/health` не отвечает,
  диск заполнен или нет свежего бэкапа; нужен `BACKUP_CHAT_ID` в `.env`.
